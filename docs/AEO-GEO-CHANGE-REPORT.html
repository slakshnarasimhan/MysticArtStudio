AEO/GEO Change Report

Project: MysticArtStudio (Artbrush domain)
Focus: AI citation readiness and answer extraction quality

This report summarizes the major AEO/GEO improvements implemented across the website, with clear examples of what changed and why each change improves scoring.

Estimated AEO/GEO uplift: ~35–39% to ~58–68%

1) Structured Data Refactor (High Impact)

Change made: JSON-LD was flattened and made page-specific.

  • Removed graph indirection patterns and made schema explicit.
  • Applied one dominant type per page.
  • Added inlined author, publisher, and page-level context.

Example

index.html now uses WebPage with mainEntityOfPage, mainEntity, author, and publisher.

Why it matters

AEO tools and LLM pipelines parse explicit top-level entities more reliably than nested or indirect schema.

2) Schema Type Coverage Across All Core Pages

Change made: Each page now maps to an appropriate schema type.

Page Schema Type AEO Benefit
/ WebPage Clear site-level entity for summary answers
/brand.html Service Improves service-intent query matching
/merchandise.html CollectionPage + Products Better extraction for product and offer answers

3) Canonical and Domain Normalization (High Impact)

Change made: All canonical and schema URLs were standardized to https://artbrush.co.

Example

Canonical tags now consistently point to the live domain (for example https://artbrush.co/brand.html).

Why it matters

Reduces source ambiguity and improves confidence when AI systems select a canonical citation target.

4) Freshness Signals and Date Completeness (High Impact)

Change made: Added and normalized publication/modification signals.

  • article:published_time and article:modified_time
  • meta name="date" and meta name="last-modified"
  • Schema datePublished and dateModified
  • Sitemap <lastmod> for every URL

Why it matters: AEO scorers use temporal signals to evaluate answer relevance and freshness.

5) Automated Freshness Pipeline (Sitemap lastmod)

Change made: Built an automated process so freshness does not rely on manual updates.

  • scripts/update-sitemap.js computes lastmod from git history.
  • .github/workflows/update-sitemap.yml runs on push to main and commits sitemap changes.

Why it matters: Prevents stale dates, a common AEO audit failure.

6) Reader-Friendly Extractability Enhancements

Change made: Added concise Q&A blocks on key pages, later relabeled to Common Questions to keep UX natural.

Example

Q&A appears in plain page content and is paired with FAQPage schema.

Why it matters

Improves extraction into direct answer snippets while staying readable for humans.

7) Technical Delivery Improvements Supporting AEO

  • defer on local script loading.
  • loading="lazy" and decoding="async" on images.
  • Above-the-fold image uses loading="eager" + fetchpriority="high".

Why it matters: Better render stability and faster content visibility improve crawl reliability and answer extraction quality.

Conclusion

The website moved from basic SEO metadata to a strong AEO/GEO foundation built on explicit schema, freshness automation, and citation-friendly structure. The most important gains come from schema clarity, date completeness, and canonical consistency.

This report focuses on changes actually implemented in the repository and their direct scoring implications.
